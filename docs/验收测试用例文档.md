# TRMD 验收测试用例文档

## 文档信息

- **项目名称**: Telegram_Restricted_Media_Downloader (TRMD)
- **版本**: 2.0.0
- **编写日期**: 2026-06-22
- **测试环境**: Windows 11, Python >= 3.12

## API Schema 说明

本项目使用 FastAPI 框架，API Schema 通过 OpenAPI 自动生成。

### 访问方式

- **Swagger UI**: `http://localhost:8000/docs` (开发/测试环境)
- **ReDoc**: `http://localhost:8000/redoc` (开发/测试环境)
- **OpenAPI JSON**: `http://localhost:8000/openapi.json` (开发/测试环境)
- **离线 Schema**: `docs/openapi.json`

### 环境控制

Swagger UI 通过环境变量 `TRMD_ENV` 控制：
- 非生产环境：启用 Swagger UI
- 生产环境 (`TRMD_ENV=production`)：禁用 Swagger UI

### 测试工具

- **测试数据工厂**: `tests/fixtures/data_factories.py`
- **测试文件准备**: `tests/fixtures/prepare_test_files.py`
- **断言辅助函数**: `tests/helpers/assertions.py`

## 测试范围说明

### 功能入口点约束
根据项目最新要求，批量下载功能的入口点已限制为：
1. **Web API 接口** - 通过 FastAPI WebUI 进行批量任务配置和执行
2. **Bot 接口** - 通过 Telegram Bot 命令进行批量操作

**已移除功能**: CLI 交互式链接输入功能已完全移除，不再支持通过命令行交互输入下载链接。

### 测试模块划分
1. Web API 接口测试
2. Bot 接口测试
3. 核心功能测试
4. 配置管理测试
5. 系统约束测试

## 一、Web API 接口测试用例

### 1.1 认证模块 (Auth)

#### TC-WEB-AUTH-001: Token 生成与验证
**优先级**: P0 (最高)
**模块**: 认证
**功能点**: Token 生成、验证、刷新

**前置条件**:
- Web API 服务已启动 (默认端口 8000)
- Bot 已启动并可通过 /web 命令生成 Token

**测试步骤**:
1. 通过 Bot 发送 `/web` 命令获取 Token
2. 使用 Token 调用 `/api/auth/me` 接口
3. 检查返回的 Token 状态信息
4. 调用 `/api/auth/refresh` 刷新 Token
5. 使用新 Token 再次调用 `/api/auth/me`

**预期结果**:
1. Bot 返回包含 Token 的 WebUI 链接
2. `/api/auth/me` 返回 Token 有效状态、过期时间、创建时间、使用次数
3. Token 刷新成功，返回新 Token
4. 旧 Token 失效，新 Token 可正常使用

**自动化测试要点**:
- 验证 Token 格式 (UUID 格式)
- 验证 Token 有效期 (默认 1 小时)
- 验证 Token 使用次数统计
- 验证刷新后旧 Token 状态

**前置条件**:

**预期结果**:

**自动化测试要点**:

- 验证错误响应格式一致性

#### TC-WEB-AUTH-003: Token 撤销功能
**优先级**: P1
**模块**: 认证
**功能点**: 通过 Bot 撤销所有 Token

**前置条件**:
- Bot 已启动

**测试步骤**:
1. 通过 Bot 发送 `/web` 命令生成 Token A

3. 通过 Bot 发送 `/web_revoke` 命令
4. 使用 Token A 调用 `/api/tasks`

**预期结果**:
1. `/web_revoke` 返回撤销数量 (2 个)
2. Token A 和 Token B 都失效
3. 所有使用已撤销 Token 的请求返回 401

**自动化测试要点**:
- 验证撤销计数准确性
- 验证批量撤销功能
- 验证撤销后 Token 状态

**测试步骤**:
1. 调用 `POST /api/tasks` 创建下载任务

1. 任务创建成功，返回 task_id
2. 任务状态为 "pending"
3. 任务详情包含正确的 chat_id、task_type、created_at

**自动化测试要点**:
- 验证 task_id 格式 (task_xxxxxxxx)
- 验证任务状态枚举值
- 验证创建时间格式 (ISO 8601)
