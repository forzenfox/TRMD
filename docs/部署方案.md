# TRMD Docker 部署方案

## 1. 概述

本文档描述 TRMD（Telegram Restricted Media Downloader）的 Docker 生产部署方案。

### 部署原则

- 镜像由 CI 流水线构建并推送至 `ghcr.io`，**生产环境不直接构建镜像**
- 数据与代码分离，所有持久化数据位于 `deploy/` 目录下
- 通过一键脚本完成部署、重启、清理操作

---

## 2. 目录结构

```
TRMD/
├── deploy/                          # 部署目录，与项目代码分离
│   ├── .env                         # 部署参数（镜像标签、端口号等）
│   ├── docker-compose.yml           # 服务编排
│   ├── config/
│   │   └── config.yaml              # 应用配置（用户填写，只读挂载）
│   ├── data/
│   │   └── .trmd/                   # 数据库及运行时数据（trmd.db + interaction_state.json）
│   ├── logs/                        # 日志文件（trmd.log）
│   ├── sessions/                    # Telegram 会话文件
│   ├── downloads/                   # 下载文件
│   ├── temp/                        # 临时文件（下载过程中）
│   ├── form/                        # 表单数据
│   ├── deploy.sh                    # 一键部署
│   ├── restart.sh                   # 一键重启
│   └── cleanup.sh                   # 一键清理
├── docs/                            # 项目文档
├── module/                          # 项目代码
├── Dockerfile                       # 运行时镜像构建文件
├── Dockerfile.base                  # 基础镜像构建文件
└── docker-compose.yml               # 本地开发用 compose
```

> **说明**：`deploy/` 下的目录在首次部署时自动创建，无需手动 mkdir。

## 3. 镜像管理

### 3.1 镜像仓库

| 镜像 | 推送位置 | 用途 |
|------|----------|------|
| `ghcr.io/<owner>/trmd-base:latest` | CI 流水线 base job | 构建缓存层，间接依赖 |
| `ghcr.io/<owner>/trmd:<tag>` | CI 流水线 build job | 运行时镜像，部署直接使用 |
| `ghcr.io/<owner>/trmd:latest` | CI 流水线 build job | 最新稳定版 |

### 3.2 镜像标签策略

- git tag 触发：`v1.2.3` → 镜像 tag `1.2.3` + `latest`
- 手动触发：可指定任意 tag

### 3.3 更新策略

部署和重启脚本均先拉取最新镜像再启动容器，确保每次部署使用最新版本。

## 4. 配置文件

### 4.1 `.env` — 部署参数

```env
# 镜像配置
IMAGE_NAME=ghcr.io/<owner>/trmd
IMAGE_TAG=latest

# 端口映射
HOST_PORT=8000

# 时区
TZ=Asia/Shanghai

# 容器名
CONTAINER_NAME=trmd
```

### 4.2 `config/config.yaml` — 应用配置

从项目根目录 `config.example.yaml` 复制并填写实际配置（api_id、api_hash、bot_token 等）。

> 首次部署前必须完成此文件的配置，否则容器启动后将无法正常运行。

## 5. 服务编排（docker-compose.yml）

```yaml
services:
  trmd:
    image: ${IMAGE_NAME}:${IMAGE_TAG}
    container_name: ${CONTAINER_NAME}
    restart: unless-stopped
    stdin_open: true
    tty: true
    ports:
      - "${HOST_PORT}:8000"
    volumes:
      # 配置（只读挂载）
      - ./config/config.yaml:/app/config.yaml:ro
      # 数据库及运行时数据
      - ./data/.trmd:/app/.trmd
      # 日志
      - ./logs:/app
      # 数据目录
      - ./sessions:/app/sessions
      - ./downloads:/app/downloads
      - ./temp:/app/temp
      - ./form:/app/form
    environment:
      - TZ=${TZ}
```

### 挂载点说明

| 容器内路径 | 宿主机路径 | 读写 | 用途 |
|-----------|-----------|------|------|
| `/app/config.yaml` | `deploy/config/config.yaml` | `ro` | 应用配置文件 |
| `/app/.trmd` | `deploy/data/.trmd` | `rw` | SQLite 数据库 (trmd.db) + 运行时状态 |
| `/app/trmd.log` | 写入 `deploy/logs/` | `rw` | 日志文件（目录挂载，文件自动写入） |
| `/app/sessions` | `deploy/sessions/` | `rw` | Telegram 会话文件 |
| `/app/downloads` | `deploy/downloads/` | `rw` | 已下载文件 |
| `/app/temp` | `deploy/temp/` | `rw` | 下载过程中的临时文件 |
| `/app/form` | `deploy/form/` | `rw` | 表单数据 |

> **日志挂载说明**：日志文件 `trmd.log` 写入容器内的 `/app/` 目录，将 `deploy/logs/` 挂载到 `/app` 后，日志文件会被写入宿主机 `deploy/logs/trmd.log`。

## 6. 服务器初始化操作

以下操作在云服务器上首次部署时执行，**仅需执行一次**。

### 6.1 安装依赖

```bash
# Docker（Ubuntu/Debian）
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# 退出当前 SSH 会话后重新登录，或执行 newgrp docker 立即生效

# Docker Compose（如未随 Docker 安装）
sudo apt install docker-compose-plugin

# 验证
docker --version
docker compose version
```

### 6.2 创建部署目录

```bash
mkdir -p /opt/trmd_plus
cd /opt/trmd_plus
```

### 6.3 获取部署文件

```bash
# 方式一：clone 整个仓库（推荐，保持与 CI 一致）
git clone https://github.com/<owner>/TRMD.git .
# 注意：clone 后仓库根目录即 /opt/trmd_plus，deploy/ 子目录即为部署目录

# 方式二：仅下载 deploy 目录（节省空间）
# 需要手动创建 deploy/ 下的子目录结构
```

### 6.4 创建预置目录结构

```bash
cd /opt/trmd_plus/deploy
mkdir -p config data/.trmd logs sessions downloads temp form
```

### 6.5 初始化配置文件

```bash
# 从项目示例配置创建应用配置
cp ../config.example.yaml config/config.yaml

# 编辑配置，填入 Telegram API 凭证
vim config/config.yaml
# 必填项：credential.api_id、credential.api_hash、credential.bot_token（可选）
```

### 6.6 配置部署参数

```bash
# 创建 .env 文件
cat > .env << 'EOF'
# 镜像配置（将 <owner> 替换为你的 GitHub 用户名）
IMAGE_NAME=ghcr.io/<owner>/trmd
IMAGE_TAG=latest

# 端口映射（宿主机端口:容器端口，默认 8000）
HOST_PORT=8000

# 时区
TZ=Asia/Shanghai

# 容器名
CONTAINER_NAME=trmd
EOF
```

### 6.7 首次部署验证

```bash
# 检查目录结构是否完整
ls -la
# 应包含：config/ data/ logs/ sessions/ downloads/ temp/ form/ .env

# 确认配置文件已填写
cat config/config.yaml | grep -E "api_id|api_hash"

# 执行部署
./deploy.sh
```

## 7. 一键部署脚本（deploy.sh）

### 执行流程

```
1. 前置检查
   ├── 检查 Docker 是否安装
   ├── 检查 Docker Compose 是否安装
   └── 检查 config/config.yaml 是否存在

2. 停止旧容器
   ├── docker compose down（保留数据卷）
   └── 忽略"服务未定义"等错误

3. 拉取最新镜像
   └── docker compose pull

4. 启动新容器
   ├── docker compose up -d
   └── 等待 3 秒后检查容器状态

5. 验证部署
   ├── 显示容器运行状态
   └── 提示查看日志命令
```

### 使用方式

```bash
# 部署 latest 版本（.env 默认）
cd deploy
./deploy.sh

# 部署指定版本
IMAGE_TAG=v1.2.3 ./deploy.sh
```

## 9. 一键清理脚本（cleanup.sh）

### 清理策略

| 项目 | 默认行为 | 说明 |
|------|---------|------|
| 容器实例 | **清理** | `docker compose down` 停止并移除容器 |
| `temp/` | **清理** | 下载临时文件，可安全删除 |
| `form/` | **清理** | 表单数据 |
| `logs/` | **清理** | 日志文件 |
| `sessions/` | **保留** | Telegram 会话，删除后需重新登录 |
| `downloads/` | **保留** | 已下载文件 |
| `data/.trmd/` | **保留** | 数据库文件，包含任务记录、缓存、配置状态 |

### 可选参数

| 参数 | 效果 |
|------|------|
| `--purge-data` | 同时清理 `data/.trmd/`（数据库） |
| `--purge-all` | 清理所有数据（含 sessions、downloads、数据库） |

### 使用方式

```bash
cd deploy

# 默认清理（保留 sessions、downloads、数据库）
./cleanup.sh

# 清理所有数据
./cleanup.sh --purge-data

# 清理所有数据（含 sessions、downloads）
./cleanup.sh --purge-all
```

## 10. 部署流程示例

### 首次部署

> 首次部署前，请先完成 [第 6 节「服务器初始化操作」](#6-服务器初始化操作) 中的步骤（安装依赖、创建目录、获取文件、配置参数）。

```bash
# 1. 确认已进入部署目录
cd /opt/trmd_plus/deploy

# 2. 确认目录结构完整
ls -la
# 应包含：config/ data/ logs/ sessions/ downloads/ temp/ form/ .env

# 3. 一键部署
./deploy.sh

# 4. 查看运行日志
docker compose logs -f
```

### 版本更新

```bash
# 方式一：部署脚本（推荐，会自动拉取最新镜像）
cd /opt/trmd_plus/deploy
./deploy.sh

# 方式二：手动操作
cd /opt/trmd_plus/deploy
docker compose down
docker compose pull
docker compose up -d
```

## 11. 数据持久化说明

### 必须保留的数据

| 数据 | 位置 | 说明 |
|------|------|------|
| Telegram 会话 | `deploy/sessions/` | 登录凭证，删除后需重新扫码/输入验证码 |
| 数据库 | `deploy/data/.trmd/trmd.db` | 任务记录、缓存、仓库索引等全部运行时数据 |
| 配置文件 | `deploy/config/config.yaml` | 应用配置 |

### 可安全清理的数据

| 数据 | 位置 | 说明 |
|------|------|------|
| 临时文件 | `deploy/temp/` | 下载中断后残留的 `.temp` 文件 |
| 表单数据 | `deploy/form/` | 临时表单缓存 |
| 日志文件 | `deploy/logs/trmd.log` | 日志文件（默认上限 200MB，自动轮转） |

## 13. 故障排查

### 容器启动后立即退出

```bash
# 查看容器日志
cd deploy && docker compose logs

# 常见原因：
# - config/config.yaml 未正确配置凭证
# - 数据目录权限不足
# - 端口被占用
```

### 数据库文件损坏

```bash
# 清理数据库（注意：会丢失所有任务记录）
cd deploy
./cleanup.sh --purge-data
./deploy.sh
```

### 需要重新登录 Telegram

```bash
# 删除会话文件后重启
cd deploy
rm -rf sessions/*
./restart.sh
```
