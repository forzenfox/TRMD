# TRMD 目录结构优化计划 - 阶段五（最终清理）

## 概述

在完成前四阶段的目录结构优化后，仍有少量遗留任务需要收尾。本阶段聚焦于：
1. 将 `tests/unit/` 根级残留的 7 个测试文件归入对应子目录
2. 删除 `module/core/models/` 空壳目录（仅剩 re-export `__init__.py`）

## 具体变更

### 任务 1：移动 7 个测试文件

使用 `git mv` 操作，无需修改文件内部内容：

| 操作 | 命令 |
|------|------|
| `tests/unit/test_sqlmodel_task.py` | `git mv → tests/unit/core/task/test_sqlmodel_task.py` |
| `tests/unit/test_sqlmodel_cache.py` | `git mv → tests/unit/core/cache/test_sqlmodel_cache.py` |
| `tests/unit/test_sqlmodel_repository.py` | `git mv → tests/unit/core/repository/test_sqlmodel_repository.py` |
| `tests/unit/test_sqlmodel_token.py` | `git mv → tests/unit/core/auth/test_sqlmodel_token.py` |
| `tests/unit/test_data_model_v2.py` | `git mv → tests/unit/core/task/test_data_model_v2.py` |
| `tests/unit/test_ingest_grouping.py` | `git mv → tests/unit/core/task/test_ingest_grouping.py` |

**注意**：`test_data_model_v2.py` 第 17 行和第 86 行引用了 `module.core.models`，移动后该路径仍然有效（`models/__init__.py` 保留直到任务 2），所以移动操作本身不会导致导入失败。

### 任务 2：删除 `module/core/models/` 空壳目录

**步骤 2.1**：将 `models/__init__.py` 中的 re-export 内容合并到 `core/__init__.py`。

当前 `core/__init__.py` 内容：
```python
from module.core.task import TaskManager
from module.core.auth import TokenManager
from module.core.cache import CacheManager
from module.core.monitor import Monitor
from module.core.repository import RepositoryDB, RepositoryManager
# + __getattr__ for FileManager
```

需要添加的导出（来自 `models/__init__.py`）：
```python
from module.core.task.models import TaskItemRecord, TaskRecord
from module.core.repository.models import (
    FileDistributionRecord,
    RepositoryFileRecord,
    RepositorySourceRecord,
)
from module.core.cache.models import CacheEntryRecord, CacheParamRecord
from module.core.auth.models import TokenRecordDB
```

**步骤 2.2**：更新 `test_data_model_v2.py` 中的导入路径。

将第 17 行的：
```python
from module.core.models import (
    RepositorySourceRecord,
    TaskItemRecord,
    TaskRecord,
    ...
)
```
更新为：
```python
from module.core import (
    RepositorySourceRecord,
    TaskItemRecord,
    TaskRecord,
    ...
)
```

将第 86 行的：
```python
from module.core.models import __all__ as models_all
```
更新为：
```python
from module.core import __all__ as models_all
```

**步骤 2.3**：删除 `module/core/models/` 目录。

### 不做的事项

| 事项 | 原因 |
|------|------|
| `core/` 根级 14 个文件进一步分组 | `db.py`/`enums.py`/`constants.py`/`parser.py`/`language.py` 是全局底层组件，放在根级更清晰；再分组收益有限且引入大量导入变更和循环导入风险 |
| `docs/` 归档整理 | 非目录结构问题，不影响开发和维护 |
| `web/vendor/` 第三方库处理 | 当前方式保证离线可用性 |

## 假设与决策

- 所有 `test_sqlmodel_*.py` 文件内部导入路径使用 `module.core.(subpackage).models` 格式，移动后无需修改
- `test_data_model_v2.py` 仅引用了 `module.core.models`，需在删除 models/ 前更新
- `test_ingest_grouping.py` 无外部导入依赖，纯函数测试，移动后无影响
- `test_constraints.py` 使用 `Path(__file__).parent.parent.parent` 定位 `config.yaml`，移动后路径需验证

## 验证步骤

1. 移动 7 个测试文件后，运行 `python -m pytest tests/unit/ -q` 确认全部通过
2. 更新 `core/__init__.py` 和 `test_data_model_v2.py` 后，再次运行测试
3. 删除 `models/` 目录后，运行 `python -m pytest tests/unit/ -q` 确认无 ModuleNotFoundError
4. 运行 `ruff check module/ tests/` 确认无新增错误
5. 最终 `git status` 确认变更文件正确
